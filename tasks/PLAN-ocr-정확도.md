# 기획 — 사진 입력 정확도 (레인 C)

날짜: 2026-08-31
발단: "OCR이 이미지 사진을 거의 제대로 못 읽는데 VLM으로 보완할 수 있을까"

## 한 문장

**지금 실패하는 것은 읽기가 아니라 세기다.**

## 0. 전제 정정 — 이미 100% VLM이다

`ocr_wongoji.read_page()`가 이미지를 base64로 실어 `llm_host` 어댑터에 그대로 보낸다.
Tesseract·PaddleOCR 같은 고전 OCR 엔진은 저장소에 한 줄도 없다. 그러니 "VLM으로
보완한다"는 이미 도달한 상태이고, 개선의 지렛대는 **VLM을 더하는 것이 아니라 VLM에게서
세는 일을 뺏는 것**에 있다.

이 구분을 먼저 못 박는 이유: "VLM을 붙이자"로 방향을 잡으면 이미 있는 것을 또 만들고,
정작 실패하는 지점은 그대로 남는다.

## 1. 지금까지의 실측

`_workspace/06_ocr-dev_notes.md`, 2026-08-31, grok-4-fast, 렌더러로 만든 **인쇄체**
원고지 1장. 원문에 조사 오류 2건을 심어 두었다.

| 지표 | 값 | 판정 |
|------|-----|------|
| 교정 침묵률 | 1.00 (`동생가`·`아이스크림를` 둘 다 생존) | PASS |
| CER (공백 제외) | 0.000 | PASS |
| **칸 정렬** | 2·3행이 21칸으로 와서 정규화가 잘라 냄 | **FAIL** |
| 손글씨 | **미측정** | — |

**세 지표 중 하나만 실패했고, 그 하나가 결과를 망친다.** 글자를 전부 맞게 읽고도 칸이
밀리면 `먹고 싶어서` → `먹고싶어서`, `된다고` → `된다 고`가 된다. 띄어쓰기는 실측
표기 오류의 50.5%를 차지하는 유형이라, 이대로 첨삭하면 **학생이 맞게 쓴 띄어쓰기를
틀렸다고 지적한다.** 교사 눈에는 "OCR이 엉망"으로 보인다.

`tasks/lessons.md`에 이미 두 줄로 적혀 있던 것이 여기서 합쳐진다.

- *"OCR의 CER이 0이어도 첨삭은 틀릴 수 있다. 칸이 한 칸 밀리면 띄어쓰기가 달라진다."*
- *"비전 모델이 행 길이를 정확히 지키지 않는다(20칸 요청에 21칸)."*

## 2. 원인 가설과 판별법

증상은 하나인데 원인 후보가 넷이다. **고치기 전에 가른다.**

| # | 가설 | 근거 | 판별법 | 비용 |
|---|------|------|--------|------|
| H1 | 모델 등급이 낮다 | `data/settings.json`(gemini-3.7-flash)이 `.env`(grok-4.6)를 덮고 있다. `detect_provider()`가 settings를 먼저 본다 | 같은 사진을 등급별로 돌려 지표 비교 | 낮음 |
| H2 | **세기 부담** | 한 장 400칸을 한 번에 세라고 요구. 21칸 사고가 실측됨 | 행 길이 위반률을 잰다. 행 단위로 잘라 주면 사라지는가 | 낮음 |
| H3 | 격자 규격 불일치 | `NCOLS = 20` 하드코딩. 실제 원고지가 10×20이면 첫 행부터 어긋난다 | 사진의 실제 칸 수를 세어 대조 | 낮음 |
| H4 | 전처리 부재 | EXIF 회전·기울기·그림자·해상도를 그대로 전송 | 보정 전후 지표 비교 | 중간 |

H2를 주범으로 본다. 인쇄체·CER 0.000에서도 칸이 밀린 것은 읽기 능력의 문제가 아니기
때문이다. 다만 **손글씨 실사진에서는 순위가 바뀔 수 있다** — 그래서 P0가 먼저다.

## 3. 단계

### P0. 계측 (선행. 건너뛰지 않는다)

측정 수단이 없으면 어느 가설이 맞았는지도, 고쳐서 나아졌는지도 말할 수 없다. 지금
저장소에는 첨삭 정확도 스크립트(`eval_accuracy.py`)만 있고 **OCR 지표 스크립트가 없다.**

| 산출물 | 내용 |
|--------|------|
| `tests/corpus/ocr/` | 이미지 + 정답 격자(고정폭 문자열). 인쇄체 기존 1장 + **손글씨 실사진** |
| `.claude/skills/wongoji-eval/scripts/eval_ocr.py` | CER · 칸 정렬 정확도 · 교정 침묵률 · **행 길이 위반률** |
| `tests/corpus/ocr/_baseline.json` | 지표별 기준선 |

행 길이 위반률을 새 지표로 추가한다. H2의 직접 측정치이고, 정규화가 잘라 낸 순간
이미 손실이 확정되므로 잘리기 **전에** 세야 한다.

**첨삭 F1과 절대 섞지 않는다.** 섞으면 점수가 떨어졌을 때 규칙 탓인지 OCR 탓인지 못
가리고, 멀쩡한 맞춤법 규칙을 헛되이 고치게 된다.

**P0의 입력이 하나 막혀 있다: 실패하는 손글씨 사진.** 인쇄체 1장으로 낸 침묵률 1.00과
CER 0.000을 손글씨에 옮겨 적으면 안 된다. 사진 없이 P1 이후를 진행하면 인쇄체에만
맞춘 튜닝이 된다.

### P1. 저비용 교정 (코드 소량, 즉시)

| 항목 | 내용 | 왜 |
|------|------|-----|
| OCR 전용 모델 분리 | 설정에 `ocr_model`을 둔다. 첨삭은 추론 강한 모델, OCR은 비전 강한 모델 | 지금은 한 모델이 둘을 겸한다. 최적점이 다르다 |
| 설정 우선순위 노출 | `/api/health`와 설정 화면에 **실제로 도는** provider·model을 찍는다 | `.env`에 grok을 적어 두고 flash로 돌고 있었다. 조용한 불일치 |
| EXIF 회전 보정 | `ImageOps.exif_transpose()` | 세로로 찍은 폰 사진이 눕는다 |
| 긴 변 리사이즈 | 상한 픽셀로 축소 후 전송 | 2000px+ 원본은 토큰만 먹고 정확도를 안 올린다 |
| `ncols` 자동 추정 | 이미지에서 세로 격자선을 세어 제안, 교사가 확인 화면에서 확정 | H3. 하드코딩 20을 계약이 아니라 기본값으로 낮춘다 |

Pillow 12.3·numpy 2.2가 matplotlib 의존으로 **이미 들어와 있다.** 격자선 검출에 새
의존성이 필요 없다(투영 프로파일이면 충분하고, OpenCV는 Vercel 번들에 무겁다).

### P2. 선택적 행 재호출 — 핵심

세기 부담을 없애는 정공법은 행 단위 호출이지만, 20행이면 호출이 20배가 된다. 교사가
한 학급 25명을 올리는 앱에서 지연과 비용이 감당되지 않는다.

**그래서 전량이 아니라 실패한 행만 다시 부른다.**

```
1차: 한 장 통째로 호출 (지금과 같다)
  ↓
검증: 행마다 len(cells) == ncols 인가
  ↓
위반 행만 → 격자 가로선으로 그 행을 크롭 → 행 하나만 다시 호출
  ↓                                        (모델은 20칸만 세면 된다)
2차에도 위반 → 자르지 않고 low_conf로 승격해 교사에게 넘긴다
```

이 설계의 이점:

- **비용이 거의 안 는다.** 인쇄체 실측에서 위반은 20행 중 2행이었다
- **모델이 세는 범위가 400칸에서 20칸으로 준다.** H2를 직접 겨냥한다
- **실패가 격리된다.** 한 행의 오차가 다른 행으로 번지지 않는다
- 격자 검출이 실패해도 1차 결과가 남는다. **OCR 경로가 통째로 죽지 않는다**

`normalize_rows()`의 현재 동작(초과분을 잘라 내고 경고)을 바꾼다. **잘린 것이 공백이
아니라 글자면 본문이 소실된다.** 자르기는 최후 수단이고, 그전에 재호출을 넣는다.

### P3. 확인 화면 — 밀림을 고치는 도구

지금 확인 화면은 칸 단위 편집만 준다. 한 칸 밀린 행을 고치려면 교사가 20칸을 **전부
다시 쳐야 한다.** 사진으로 입력하는 이유가 재타이핑을 없애는 것인데, 여기서 재타이핑이
되살아난다. 체감상 "OCR이 못 읽는다"의 절반은 여기서 온다.

| 도구 | 조작 |
|------|------|
| 행 밀기 | 이 행을 좌/우로 한 칸 이동 |
| 칸 삽입·삭제 | 이 칸 앞에 빈 칸 넣기 / 이 칸 지우고 당기기 |
| 행 길이 위반 표시 | 1차에서 `ncols`를 넘겨 온 행을 눈에 띄게 |
| 원본 나란히 보기 | 해당 행의 크롭 이미지를 칸 격자 옆에 |

**칸 단위 입력을 통짜 textarea로 되돌리지 않는다.** 칸 정보가 깨지면 O8을 영영 못 잡는다.

### P4. 게이트 편입

`wongoji-qa`의 출시 게이트에 OCR 게이트를 별도 항목으로 넣는다. 첨삭 게이트와 합산하지
않는다.

## 4. 게이트 수치

손글씨 실사진으로 기준선을 세운 뒤 확정한다. 잠정 목표:

| 지표 | 목표 | 실패 시 |
|------|------|--------|
| 교정 침묵률 | ≥ 0.95 | **즉시 FAIL.** 다른 지표가 아무리 좋아도 출시하지 않는다 |
| 칸 정렬 정확도 | ≥ 0.98 | 재호출 경로 보강 |
| 행 길이 위반률 | ≤ 0.02 | 재호출 경로 보강 |
| CER (손글씨) | ≤ 0.05 | 모델 등급 재검토 |
| 텍스트 붙여넣기 경로 | 무손상 | **즉시 FAIL** |

침묵률을 최상위에 두는 이유는 이 레인의 한 문장 그대로다 — OCR이 맞춤법을 고치면
첨삭기는 죽는다. 침묵률 실패는 조용하다. CER은 눈에 보이지만 침묵률은 "오류가
없습니다"로 나타난다.

## 5. 안 하는 것

- **고전 OCR 도입.** 한글 손글씨 + 격자 겹침에서 무너진다. 이미 내린 결정을 다시 열지 않는다
- **이미지 영구 보관.** 학생 손글씨는 개인정보다. 재호출용 크롭도 요청 안에서만 산다
- **확인 화면 우회 경로.** 정확도가 아무리 올라도 게이트를 열지 않는다. 오인식과 학생 오류를 기계는 구분할 수 없다
- **OCR 지표와 첨삭 F1 합산.** 원인을 못 가리게 된다
- **OpenCV 도입.** 투영 프로파일로 충분하고, 서버리스 번들이 무거워진다
- **전량 행 단위 호출.** 비용·지연이 시범 운영을 막는다. 선택적 재호출로 간다

## 6. 리스크

| 리스크 | 대응 |
|--------|------|
| 손글씨 실사진에서 침묵률이 무너진다 | 프롬프트 강화 1회 → 그래도 남으면 모델 교체. 그 유형을 교사 확인 필수로 승격 |
| 격자선 검출이 실사진에서 실패(기울기·그림자) | 1차 결과를 그대로 살리고 재호출만 건너뛴다. **OCR 경로가 죽지 않는 것이 우선** |
| 재호출로 지연이 늘어 교사가 기다린다 | 위반 행만 부르므로 대부분 0~2회. 상한을 두고 넘으면 교사에게 넘긴다 |
| HEIC(아이폰 기본)를 모델이 못 받는다 | 미확인. P1에서 확인하고, 안 되면 업로드 시 변환 |
| 다중 페이지를 실사진으로 확인 안 했다 | P0 코퍼스에 2장짜리를 넣는다 |

## 7. 열린 질문 (진행에 필요)

1. **실패하는 손글씨 사진** — P0의 입력. 없으면 인쇄체에만 맞춘 튜닝이 된다
2. **그 원고지의 칸 규격** — 10×20인가 20×20인가. H3 판별에 필요
3. 재호출 비용 상한 — 한 장당 몇 회까지 허용하는가

## 순서

```
P0 계측 ──> H1~H4 판별 ──> P1 저비용 교정 ──> 재측정
                                                │
                            ┌───────────────────┘
                            ↓
                     P2 선택적 재호출 ──> 재측정 ──> P3 확인 화면 ──> P4 게이트
```

**각 단계 뒤에 재측정이 붙는다.** 기준선 없이 다음 단계로 넘어가지 않는다. 규칙 레인의
원칙과 같다 — 측정이 구현보다 먼저다.

모델: gemini-3.7-flash. 같은 사진을 전처리 전/후로 두 번 호출해 비교.

## 가설 판정

| # | 가설 | 판정 | 근거 |
|---|------|------|------|
| H1 | 모델 등급 | **미결** | flash로도 내용은 대체로 맞았다. 등급을 올려 재측정할 값어치는 남아 있다 |
| H2 | **세기 부담** | **확정** | 26행 중 **15행(58%)이 21칸**으로 왔다 |
| H3 | 격자 규격 | **기각** | `NCOLS = 20`이 맞다. 우측 여백 `100`~`600` 표시로 확인 |
| H4 | 전처리 부재 | **기각(원인 아님)** | EXIF Orientation=6이었으나 Gemini가 존중했다. 전/후 결과가 거의 같다 |

**H4를 원인으로 단정했다가 실측으로 뒤집혔다.** 픽셀이 누워 있는 것을 보고 확신했는데,
공급자가 EXIF를 처리하고 있었다. 전처리는 공급자 의존을 없애기 위해 남기되, 이번
실패의 원인은 아니다.

## 진짜 원인 — 모델이 아니라 우리 코드가 지웠다

모델은 글자를 잘 읽었다. 학생 오류도 살아남았다 — `가출`, `않는다면`, `되었을때`,
`가야한다`, `이런이이유로`, `만약=`. **침묵은 지켜지고 있다.**

문제는 21칸으로 온 행을 `normalize_rows()`가 **오른쪽에서 잘라 낸** 것이다. 하필
오른쪽 끝이 내용이 있는 자리다. 실제로 사라진 글자:

| 행 | 원고 | 잘린 뒤 | 소실 |
|----|------|--------|------|
| 3 | `곳입니다. 정` / `해진 시간표…` | `곳입니다.` / `해진…` | **정** |
| 12 | `보통 초등` / `학교로부터는` | `보통 초` / `학교…` | **등** |
| 16 | `이 학생들은 초` / `등학교,` | `이 학생들은` / `등학교,` | **초** |
| 17 | `거쳤으면 사` / `회에서는` | `거쳤으면` / `회에서는` | **사** |

본문에서 글자가 통째로 없어지는데 남는 것은 경고 한 줄이다. 교사가 볼 수 없다.

## 이번에 고친 것

| 파일 | 변경 |
|------|------|
| `ocr_wongoji.shrink_row()` | 넘친 행에서 **글자보다 공백을 먼저 버린다.** 꼬리 공백 → 겹공백 순 |
| `ocr_wongoji.normalize_rows()` | 글자가 넘치면 버리지 않고 `row["overflow"]`로 싣는다 |
| `ocr_wongoji.low_confidence()` | `overflow`를 교사 확인 목록에 올린다 |
| `ocr_wongoji.normalize_rows()` | 짧은 행도 경고한다. 조용히 채우면 위반률의 절반이 안 보인다 |
| `ocr_wongoji.prepare_image()` | EXIF 방향·긴 변 축소. 공급자에 기대지 않는다 |
| `eval_ocr.py` | 침묵률·칸정렬·CER·행길이위반률 |

**홑공백은 지우지 않는다.** 21칸에서 홑공백을 지워 20칸을 맞추면 띄어쓰기를 임의로
바꾸는 것이고, 띄어쓰기는 실측 오류의 50.5%다. 추측할 자리가 아니라 교사에게 넘길
자리다.

## 남은 것

1. **P2 선택적 재호출** — 원인(H2)에 대한 정공법. 위반 행만 크롭해 다시 부른다.
   58%가 위반이므로 이 사진에서는 15행을 다시 부르게 된다. 비용 재검토 필요
2. **기울기 보정이 선행돼야 한다.** 붉은 격자선 투영 검출을 시도했으나 행 방향 최대
   커버리지가 0.40에 그쳐 실패했다. 선이 픽셀 행과 나란하지 않다
3. **행 이음매 띄어쓰기.** `grid_to_text`가 행을 무조건 붙여 `곳이아니라`,
   `곳입니다.해진`을 만든다. 원고지에서 행 끝 띄어쓰기는 물리적으로 표시되지 않으므로
   격자만으로는 복원할 수 없다. **없는 띄어쓰기 오류를 만들고 있다.** 교사 확인에서
   짚거나, 이음매에서는 띄어쓰기 부호를 내지 않는 편이 낫다
4. **정답 격자 미작성.** 침묵률·칸정렬·CER의 수치를 아직 못 냈다. `keep` 후보는 확보됨
5. **제목 처리 미결** — 상단 `주제` 칸의 학생 손글씨를 첨삭 대상에 넣을지

## 기준선 (2026-08-31, gemini-3.7-flash)

| 지표 | 값 | 판정 |
|------|-----|------|
| 교정 침묵률 | **1.000** | PASS — 학생 오류가 하나도 안 고쳐졌다 |
| 칸 정렬 | 0.993 (1~7행) | 잠정. 유일한 불일치가 `정` 넘침이다 |
| CER | **0.007** | PASS — 글자는 거의 완벽하게 읽는다 |
| CER(무공백) | 0.009 | PASS |
| **행 길이 위반률** | **0.462** (12/26행) | **FAIL — 여기가 전부다** |

**한 줄: 모델은 읽고, 세지 못한다.** CER 0.007과 위반률 0.462가 같은 실행에서 나왔다.
인식 품질을 의심할 이유가 없다.

`정`·`기`·`등`·`시간`·`전`·`초`·`사`·`학`. 고치기 전에는 조용히 지워지던 것들이다.
