# 맞춤법 규칙 계층

이 앱의 결함은 대부분 여기에 있다. `rule_layer`가 잡는 결정적 오류는 **띄어쓰기·
종결부호·문단 첫 칸 3종뿐**이고, 되/돼·조사 받침·사이시옷 같은 나머지 맞춤법은
전부 LLM에 위임되어 있다. LLM은 `max_items` 상한이 있고 매번 다른 것을 고르므로,
같은 글을 두 번 넣으면 다른 오류가 잡힌다. 교사가 신뢰할 수 없는 이유다.

**규칙으로 판정 가능한 오류를 LLM에 맡기지 않는다.** 이것이 이 스킬의 한 문장이다.
실측 말뭉치에서 규칙이 담당할 수 있는 몫은 **75.9%**다. 넷 중 셋이 규칙의 일이다.

오류 유형 코드(O1~O11, C1~C4)와 혼동쌍 목록은 `references/오류유형_카탈로그.md`,
**어떤 유형을 먼저 구현할지의 실측 근거는 `references/말뭉치_근거.md`**를 읽는다.
부호 모양·원고지 규범은 `wongoji-domain`, 파이프라인 조립은 `wongoji-engine`.

## 전수와 초점의 경계

제품 결정: **표기(O1~O10)는 전수, 내용(C1~C4)만 초점 상한.**

`focus_filter`는 지금 종류를 라운드로빈으로 돌며 `MAX_SHEET_ITEMS`에서 자른다.
표기 오류가 이 상한에 걸려 잘려 나가면 "다 찾아 준다"는 약속이 깨진다. 다음처럼
나눈다.

```
표기_항목 = [c for c in merged if c["layer"] == "표기"]
내용_항목 = [c for c in merged if c["layer"] == "내용"]
drawn = 표기_항목 + focus_filter(내용_항목, max_items=내용상한)[0]
```

지면이 모자라면 항목을 버리는 대신 **원고지를 한 장 더 쓴다**. `nrows`를 늘리거나
장을 나눈다. 부호가 서로 겹쳐 못 읽히는 것이 진짜 상한이지, 숫자 16이 상한이 아니다.

`layer` 필드가 항목마다 정확해야 이 분기가 산다. `make()`의 기본값 `"표기"`에
기대지 말고 규칙마다 명시한다.

## 규칙 작성 규약

새 규칙은 `chumsak_app.py`에 `rule_{유형}()` 형태로 하나씩 추가하고 `rule_layer`가
모은다. 규칙 하나는 다음 다섯을 모두 갖춘다.

1. **유형 코드** — `c["type"] = "O1"`. 평가 리포트가 유형별로 재현율을 쪼갠다
2. **결정적 판정** — 같은 입력이면 항상 같은 출력. 확률·모델 호출 금지
3. **부호 매핑** — 카탈로그가 정한 kind를 쓴다. 임의로 고르지 않는다
4. **오탐 억제 조건** — 카탈로그의 5개 원칙 중 이 규칙에 걸리는 것을 코드로 막는다
5. **양성·음성 픽스처** — 잡아야 할 문장과 잡으면 안 되는 문장을 코퍼스에 함께 낸다

음성 픽스처 없이 규칙을 올리지 않는다. 재현율만 올리는 규칙은 오탐으로 정밀도를
깎아 총점을 떨어뜨린다.

## 판정 강도 3단계

모든 오류가 같은 확신도를 갖지 않는다. 확신도를 `confidence`로 남기고 소비처가
다르게 쓴다.

| 강도 | 근거 | 처리 |
|------|------|------|
| `certain` | 형태만 보면 판정된다 (몇일, 오랫만, 받침 조사, 읍니다) | 지면에 그린다 |
| `likely` | 문맥을 봐야 하나 규칙이 대부분 맞는다 (되/돼, 안/않, 로서/로써) | 지면에 그리되 사유에 근거를 쓴다 |
| `uncertain` | 문맥 의존이 커서 규칙이 자주 틀린다 (사이시옷 신조어, 띄어쓰기 관용) | `held`로 보내 교사 목록에만 올린다 |

`uncertain`을 지면에 그리면 오탐이 교사 눈앞에 온다. 목록에 두면 교사가 고를 수 있다.

## 규칙 계층과 LLM 계층의 역할 분담

```
규칙 계층  → O1~O10 중 결정적으로 판정되는 것 전부. 상한 없음
LLM 계층   → C1~C4(내용) + 규칙이 uncertain으로 남긴 표기 후보의 문맥 판정
```

LLM 프롬프트에 **"규칙이 이미 잡은 유형은 다시 내지 마라"**를 넣고 잡힌 유형 코드
목록을 전달한다. 지금은 이 정보가 없어서 LLM이 띄어쓰기를 중복 제출하고, 그것이
`drop_overlaps`에서 버려지면서 정작 필요한 내용 첨삭 자리를 잡아먹는다.

## 자주 재발하는 함정

**받침 조사를 놓친다.** `학교은`, `밥를` 같은 것은 완전 결정적인데 지금 아무도 안
잡는다. 한글 음절의 종성 유무는 `(ord(ch) - 0xAC00) % 28`로 나온다. 이걸 못 잡으면
다른 규칙을 논할 자격이 없다.

**kiwi를 사전 검사기로 쓴다.** kiwi는 어떤 입력이든 최선의 분석을 내놓아 "분석 실패"가
나오지 않는다. `초콜렛`을 명사로 받고 `느꼇다`의 없는 어미 `엇`도 통과시킨다. 철자
오류에는 별도 표제어 사전이 필요하다. 다만 조사 자리에 NNG/VV가 오는 이상 분석
(`대회을` → `을/NNG`)은 **보조 신호**로 쓸 수 있다.

**형태만 보고 띄어쓰기 방향을 정한다.** `하`·`되`·`것`·`한`은 띄우는 오류와 붙이는
오류 양쪽에 상위로 나온다. 앞말 품사를 안 보고 "'하' 앞은 띄운다"로 구현하면 접미사
사례를 전부 오탐한다.

**보조용언 붙여쓰기를 오류로 잡는다.** 원칙형과 허용형이 둘 다 맞다. 오류가 아니라
권고다. 이걸 오류로 내면 과잉 첨삭이 된다.

**되/돼를 문자열 치환으로만 판정한다.** `되`를 `하`로, `돼`를 `해`로 바꿔 어느 쪽이
어미로 자연스러운지 본다. 형태소 분석 결과(kiwi)의 품사 태그를 함께 쓴다.

**마지막 문장을 뺀다.** 이미 고쳐진 결함이지만 규칙을 추가할 때마다 재발한다.
문장 순회는 `split_into_sents` 결과 전체를 돈다.

**target을 본문에 없는 문자열로 만든다.** `verify`가 통째로 버린다. `target`은
원문에서 잘라 온 부분 문자열이어야 하고, 같은 문자열이 여럿이면 `nth`를 채운다.

**오탐을 침묵으로 착각한다.** 규칙이 확신 못 해 아무것도 안 내는 것과, 틀린 것을
내는 것은 다르다. 전자는 재현율 손실, 후자는 신뢰 손실이다. 후자가 더 비싸다.

## 구현 순서 (실측 우선순위)

감으로 고르지 않는다. 오류 796건의 실측 분포가 정한 순서다. 근거는 `말뭉치_근거.md`.

| 순위 | 규칙 | 왜 여기인가 |
|------|------|------------|
| 1 | 의존명사 띄어쓰기 (O6) | 오류의 50.5%가 띄어쓰기고, 그중 최대 덩이. ETM+NNB 패턴으로 결정적 |
| 2 | 받침 조사 (O3) | 완전 결정적. 학생 글에서 지배적이고 지금 아무도 안 잡는다 |
| 3 | 사전 기반 표기 검사 (O11) | 표기 오류의 83%. 목록 없이 덮인다 |
| 4 | 접미사 -하다/-되다 (O6) | 앞말이 명사일 때만. 방향 판정이 핵심 |
| 5 | -율/-률 (O2) | 앞 음절 받침으로 결정 |
| 6 | 보조용언 (O6) | **오류가 아니라 권고.** 심각도 낮춰 held로 |

**목록이 아니라 판정기를 만든다.** 실측에서 같은 (오류→교정) 짝이 두 저장소 이상에서
반복된 경우는 0종이었다. "자주 틀리는 낱말 목록"으로는 표기 오류를 덮을 수 없다.
혼동쌍 규칙(되/돼, 왠/웬)은 목록이 짧고 확실한 것만 쓰고, 나머지는 사전 검사로 간다.

## 작업 순서

1. `references/오류유형_카탈로그.md`에서 이번에 구현할 유형을 고른다
2. 그 유형의 양성·음성 예문을 코퍼스에 먼저 넣는다 (`wongoji-eval`)
3. `eval_accuracy.py`를 돌려 **현재 재현율 0%를 확인**한다 (기준선)
4. `rule_{유형}()`을 구현한다
5. 다시 돌려 해당 유형 재현율이 오르고 **다른 유형 정밀도가 안 떨어졌는지** 본다
6. 떨어졌으면 오탐 억제 조건을 조인다. 규칙을 지우지 말고 조건을 붙인다

기준선 없이 구현부터 하면 개선을 증명할 수 없다. 3번을 건너뛰지 않는다.
