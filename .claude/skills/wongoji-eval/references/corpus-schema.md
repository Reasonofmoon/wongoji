# 골드 코퍼스 스키마

한 줄에 한 편(JSON Lines). 파일은 `tests/corpus/*.jsonl`. `_`로 시작하는 파일은
코퍼스가 아니라 부산물(`_baseline.json`)이므로 로더가 건너뛴다.

## 레코드

```json
{
  "id": "el6-일기-003",
  "grade": "초등 6학년",
  "source": "synthetic",
  "text": "오늘은 학교은 갔다 정말 재미있었다",
  "errors": [
    {"type": "O3", "span": [4, 7], "target": "학교은", "kind": "replace",
     "fix": "학교는", "confidence": "certain", "note": "받침 있는 말 뒤는 는"},
    {"type": "O7", "span": [8, 10], "target": "갔다", "kind": "punct",
     "fix": ".", "confidence": "certain", "note": "문장이 끝났는데 마침표가 없다"}
  ],
  "negatives": [
    {"type": "O6", "span": [11, 13], "target": "정말",
     "note": "강조 부사는 오류가 아니다"}
  ]
}
```

| 필드 | 필수 | 뜻 |
|------|------|-----|
| `id` | O | 코퍼스 전체에서 유일. `{학년}-{갈래}-{번호}` |
| `grade` | O | 학년. 판정 관대함이 학년에 따라 달라진다 |
| `source` | O | `synthetic`(합성) 또는 `real`(실제 학생 글, 익명화 완료) |
| `text` | O | 원문. **줄바꿈은 `\n`, 문단 첫 칸 공백을 그대로 보존한다** |
| `errors` | △ | 반드시 잡아야 하는 오류. 재현율의 분모 |
| `negatives` | △ | 잡으면 안 되는 자리. 오탐 회귀를 막는다 |

`errors`와 `negatives`가 둘 다 비면 그 레코드는 아무것도 측정하지 않는다.
검증기가 거른다.

## errors 항목

| 필드 | 필수 | 뜻 |
|------|------|-----|
| `type` | O | `O1`~`O10`, `C1`~`C4`. 카탈로그 코드 |
| `span` | O | `[시작, 끝)` 문자 인덱스. `text[시작:끝]`이 오류 부분 |
| `target` | 권장 | `text[span]`과 **글자까지 같아야 한다**. 검증기가 대조한다 |
| `kind` | O | 이 오류에 붙어야 할 교정부호 |
| `fix` | replace/insert/punct는 필수 | 고칠·넣을 글자 |
| `confidence` | 권장 | `certain` / `likely` / `uncertain` |
| `note` | 권장 | 왜 오류인지 한 줄. 실패 리포트에 그대로 나온다 |

## negatives 항목

`type`, `span`, `target`, `note`만 쓴다. `kind`·`fix`는 없다. 여기에 부호가 앉으면
**음성 픽스처 위반**으로 즉시 게이트 실패다. 카탈로그의 오탐 억제 5원칙(고유명사,
복수 표준형, 인용문 구어체, 의도된 반복, kiwi 단독 근거)마다 최소 3편을 둔다.

## span 계산 함정

**문자 인덱스는 파이썬 기준이다.** `len("학교은")`은 3이다. 자모 분리·이모지·
공백을 눈으로 세지 말고 스크립트로 만든다.

```python
i = text.index("학교은")
{"span": [i, i + len("학교은")]}
```

경계 부호(`space`, `insert`, `punct`, `newline`, `joinline`)의 span은 **부호가 앉을
자리 바로 앞 글자**를 가리킨다. 종결부호 누락이면 문장 마지막 글자다. 평가기가
경계 부호에 ±1칸 허용 오차를 두는 이유가 이것이다.

## 합성 코퍼스 생성 절차

1. **깨끗한 원문을 먼저 쓴다.** 학년·갈래에 맞는 오류 없는 글을 쓴다
2. **오류를 하나씩 주입한다.** 주입할 때 `span`을 계산해 함께 적는다. 다 쓰고 나서
   오류를 찾아 표시하면 반드시 어긋난다
3. **한 편에 유형을 3~6개 섞는다.** 한 유형만 든 글은 현실과 다르고, 유형 간
   간섭(겹침 처리, 상한)을 측정하지 못한다
4. **negatives를 같은 편에 넣는다.** 오류만 든 글은 정밀도를 측정할 수 없다
5. `validate_corpus.py`를 돌린다. 통과하기 전에는 코퍼스가 아니다

## 분포 목표

| 축 | 목표 |
|----|------|
| 학년 | 초3~4 / 초5~6 / 중1~3 각 1/3 |
| 갈래 | 일기·생활문 / 독서감상문 / 설명·주장하는 글 각 1/3 |
| 길이 | 200자 미만 / 200~600자 / 600자 이상 각 1/3 |
| 유형 | O1~O10 각각 최소 10회 출현. C1~C4는 각 5회 |
| 무오류 편 | 전체의 10%. 오류가 하나도 없는 글에 부호가 앉으면 안 된다 |

600자 이상 편이 필요한 이유: 전수 표시 정책에서 지면 상한·다중 장 분할이 여기서만
드러난다. 짧은 글만 있으면 상한 버그를 못 잡는다.

## 홀드아웃

`source: "real"` 레코드는 개발 루프에서 쓰지 않는다. 합성 코퍼스로 규칙을 튜닝하고,
실제 학생 글은 **최종 확인용으로 한 번만** 돌린다. 홀드아웃을 보면서 튜닝하면
그 글에만 맞는 규칙이 생기고 새 글에서 무너진다.

## 실제 학생 글을 구하는 경로

`source: "real"` 레코드가 없으면 홀드아웃이 없고, 합성 코퍼스에만 맞는 규칙이 생긴다.
다음은 네트워크가 아니라 **계정과 승인**의 문제라 사용자가 직접 받아야 한다.

| 자료 | 받는 곳 | 용도 | 조건 |
|------|---------|------|------|
| 국립국어원 한국어 학습자 말뭉치 | kcorpus.korean.go.kr | 오류 주석된 문장. O3·O11 패턴의 정본 | 비상업적 한정 |
| 모두의 말뭉치 | kli.korean.go.kr | 정문 말뭉치. 오류 주입용 대조군 | 로그인·이용 신청 |
| AI-Hub 어문 규범 위반 데이터 | aihub.or.kr | 규범 위반 유형별 주석 | 가입·승인 |

받으면 같은 유형 코드로 태깅해 `holdout.jsonl`에 넣는다. 확보 전까지는 리포트에
**"홀드아웃 없음 — 합성 코퍼스 과적합 위험"**을 명시한다. 숨기지 않는다.

## 학생 글을 다룰 때

원문 보관 기간과 보호자 동의 절차가 필요하다. 실제 학생 글을 코퍼스에 넣을 때는
이름·학교·지명을 익명화하고, `source: "real"`로 표시해 재배포 대상에서 뺀다.
