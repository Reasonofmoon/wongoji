# 교사 UI

브라우저는 칸을 계산하지 않는다. 서버 SVG를 붙이고 상태만 관리한다. API 필드명은 `wongoji-engine/references/api-contract.md`가 진실이다.

미학은 `frontend-ui-ux` 스킬을 따른다. 방향은 **editorial print**: 미색 지면, 본문은 명조, 교정은 빨강(`#C0392B`). Inter·Roboto·보라 그라데이션 금지. 기억 포인트는 부호가 앉은 원고지 한 장이다.

## 화면 둘

**입력 (`#view-compose`)**  
원문 붙여넣기, 학년, 초점 칩(최대 2종), 간접 첨삭 토글, 실행 버튼. 실행 중에는 격자 골격만 보여 주고, 끝나면 검토 화면으로 전환한다.

**검토 (`#view-review`)**  
기존 검토 패널. 부호 ↔ 목록 선택, 종류 칩 필터, 미검토 숨기기, 규칙 계층 일괄 승인, 총평 3단, 게이트 반려(교사만).

한 HTML에서 뷰를 전환한다. 빌드 스텝을 만들지 않는다.

## 상태 계약

`pending | approved | edited | rejected`

- 승인/기각 버튼을 다시 누르면 pending으로 돌아간다
- 수정은 사유와 `text`(넣음·고침·부호넣음)를 받는다. 사유만 고치면 대체 글자가 땅에 남는다
- 기각된 `.mk`는 흐리고 점선. 승인된 부호는 선이 조금 굵다
- 학생에게 돌려주기(PDF, `audience: student`)는 미검토 0건일 때만 활성화
- PNG(`audience: teacher`)는 미검토를 빼고 그릴 수 있다. 그 사실을 메시지에 적는다

`payloadOut`은 api-contract의 export 요청과 키가 같아야 한다.

## 정적 데모

`window.__CHUMSAK__`가 있으면 fetch를 하지 않는다. 검토는 동작하고, 내보내기만 안내 문구로 막는다. `examples/첨삭검토_데모.html`은 같은 `app.js`를 쓰도록 유지한다.

## 접근·반응

- 부호 클릭과 목록 클릭이 서로를 스크롤한다
- 1100px 이하에서 원고지 위, 목록 아래
- `lang="ko"`, 버튼 이름이 동작과 같다 ("학생에게 돌려주기" = student PDF)

## 테스트 프롬프트

1. "글을 붙여넣는 입력 화면을 검토 화면 앞에 붙여줘"
2. "수정 버튼이 대체 글자도 고치게 해줘"
3. "정적 데모에서 승인/기각은 되고 내보내기만 막히게 해줘"

## OCR 확인 화면 (2026-08-30 추가)

사진 입력이 들어오면서 화면이 하나 늘었다. 업로드와 첨삭 사이에 앉는다.

```
업로드 → OCR → [확인 화면] → 첨삭 → 검토 → 내보내기
```

**칸 단위 편집이어야 한다.** OCR 응답은 `rows[].cells[]` 격자이고, 화면이 이것을
통짜 textarea로 펼치면 칸 정보가 깨진다. 그러면 문단 첫 칸을 비웠는지가 사라지고
원고지 형식 오류를 영영 못 잡는다. 빈 칸(`ch: ""`)도 칸으로 렌더한다.

- 원본 이미지와 칸 격자를 나란히 놓는다. 교사가 눈으로 대조한다
- `conf`가 낮은 칸(기본 0.85 미만)을 눈에 띄게 표시한다. 교사가 거기부터 짚는다
- **확인 완료 버튼을 누르기 전에는 첨삭을 호출하지 않는다.** 이 게이트를 우회하는
  경로를 만들지 않는다. OCR 오인식과 학생 오류를 기계가 구분할 수 없기 때문이다
- 텍스트 붙여넣기 입력은 그대로 남긴다. OCR이 죽어도 앱은 돌아야 한다

미학은 그대로 editorial print다. 확인 화면도 대시보드가 아니라 원고지처럼 보인다.

## 정적 자산을 고친 뒤

`web/app.js`·`web/app.css`를 고치면 `index.html`의 링크 버전(내용 해시)도 갱신한다.
안 하면 브라우저가 옛 JS를 쓰면서 **새 화면이 뜨는데 아무 동작도 안 하는** 상태가 된다.
절차와 스크립트는 `references/정적자산_캐시.md`. 테스트가 어긋남을 잡는다.
