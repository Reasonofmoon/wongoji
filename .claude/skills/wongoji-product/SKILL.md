# v1 출시 제품 규칙

v1의 사용자는 **초·중등 국어 교사 한 사람**이다. 한 편의 글을 받아 첨삭본을 돌려주는 데 5분을 넘기면 안 된다.

원 기획서(`docs/기획서_원고지첨삭앱.md`)의 1단계가 출시 범위다. 2단계(사진, 회차, 학급, 학부모 발송)는 시범 운영 후에 연다.

## 넣는 것

1. 원고 붙여넣기 (학년, 초점 부호, 간접 첨삭 토글)
2. 규칙 계층 + (있으면) LLM 계층 + 게이트
3. 원고지 SVG 검토: 항목별 승인 / 수정(사유·대체글자) / 기각(되살림표)
4. 총평 3단 편집
5. PNG·PDF 내보내기. 미검토 항목이 있으면 학생용 PDF는 막는다
6. 세션이 프로세스 재시작 후에도 최근 작업을 복구한다
7. LLM 키 없이 규칙 계층만으로 데모가 된다

## 빼는 것

- 점수·등급
- 실시간 타이핑 교정
- 한글(.hwp) 파일 업로드
- 학급 명단, 로그인 SSO, 멀티테넌트
- hunspell (채택은 리서치에 있으나 v1 경로에 없음)
- Next.js·Supabase 재작성. 엔진이 Python이라 v1은 FastAPI + 바닐라 JS 한 프로세스

## 사용자 여정

```
입력 화면에서 글 붙여넣기
  → 첨삭 실행 (규칙 즉시, LLM은 있으면)
  → 검토 화면에서 부호를 항목과 오가며 승인·수정·기각
  → 총평 손질
  → 학생에게 돌려주기 (PDF) / 첨삭본 PNG
```

교사 승인 없이 학생에게 나가지 않는다. "학생에게 돌려주기"는 미검토 0건일 때만 산다.

## 출시 게이트

통과하지 못하면 출시하지 않는다.

| 게이트 | 판정 |
|--------|------|
| 입력→검토가 UI에서 끝난다 | 데모 문장에 갇히지 않음 |
| `examples/spec_예시.json` 앵커가 기대 칸과 일치 | 레이아웃 테스트 |
| 마지막 문장 종결부호 누락이 잡힌다 | 규칙 계층 |
| 기각된 들여쓰기가 원문을 들여 쓰지 않는다 | export 레이아웃 |
| 파이프라인이 `chumsak_app` 한곳 | 서버가 재조립하지 않음 |
| 점수 문자열이 UI·PDF에 없다 | grep |
| README로 로컬 실행이 된다 | uvicorn 한 줄 |

## 첨삭 밀도 정책 (2026-08-30 확정)

| 층위 | 정책 | 이유 |
|------|------|------|
| 표기 (맞춤법·띄어쓰기·부호·원고지 형식) | **전수 표시** | 정답이 하나다. 빠뜨리면 학생이 틀린 채로 익힌다. "다 찾아 준다"가 이 앱의 약속이다 |
| 내용 (겹말·상투어·호응·문단) | **초점 상한 유지** | 정답이 여럿이다. 많이 달수록 학생이 자기 글을 잃는다 |

지면이 모자라다는 것은 항목을 버릴 이유가 아니라 **장을 늘릴 이유**다. 원고지는
원래 여러 장이다.

이 정책이 흔들리면 두 가지가 동시에 깨진다. 상한을 표기에까지 걸면 사용자가 "다 못
찾는다"고 하고, 상한을 내용에서 풀면 교사가 "빨간 게 너무 많다"고 한다. 둘 다 겪은
뒤에 나온 결정이므로 되돌릴 때는 이유를 남긴다.

**여전히 넣지 않는 것:** 점수·등급, 학급 대시보드, 회차 비교, 실시간 타이핑 교정.
정확도가 올라가도 이 목록은 바뀌지 않는다.

## 범위 반전: OCR을 1단계로 (2026-08-30)

**결정:** 사진 입력(OCR)은 2단계가 아니라 **v1 필수**다. 사용자 지시로 뒤집었다.

**원래 뺐던 이유:** 인식 품질이 불확실하고 구현 비용이 크다. 텍스트 붙여넣기로도
첨삭은 된다.

**뒤집은 이유:** 붙여넣기가 된다는 것과 교사가 쓴다는 것은 다르다. 한 학급 25명을
다시 타이핑하면 **입력이 첨삭보다 오래 걸린다.** 시범 운영이 입구에서 막힌다.
OCR은 편의 기능이 아니라 채택 여부를 가르는 기능이다.

**대신 잠그는 조건 — 이것 없이 OCR을 내보내지 않는다:**

| 조건 | 이유 |
|------|------|
| **교사 확인 화면 필수** | OCR 오인식과 학생 오류를 기계가 구분할 수 없다. 확인 없이 첨삭하면 학생이 맞게 쓴 글자를 틀렸다고 배운다 |
| **자동 교정 금지** | OCR이 맞춤법을 고치면 첨삭할 오류가 사라진다. 교정 침묵률로 검증한다 |
| **텍스트 입력 경로 유지** | OCR 실패가 앱을 막지 않는다. 붙여넣기는 계속 1급 입력이다 |
| **이미지 미보관** | 학생 손글씨 사진은 개인정보다. 첨삭 후 지운다. 보관하려면 기간·동의 절차를 먼저 정한다 |
| **FastAPI 안에서 구현** | 참조 저장소는 Node다. 런타임을 늘리면 모놀리스 원칙이 깨진다 |

여전히 2단계인 것: 원고지 사진의 **자동 채점**, 학급 단위 일괄 업로드, 회차 비교.
OCR이 들어왔다고 이것들이 따라 들어오지 않는다.
