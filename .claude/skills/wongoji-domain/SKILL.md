# 원고지 첨삭 도메인

이 제품은 맞춤법 검사기가 아니다. **원고지 격자에 교정부호를 앉히는 작문 지도 도구**다. 부호 하나하나가 학생이 고쳐 쓸 지시이므로, 그릴 수 없는 지적은 첨삭이 아니다.

상세 규정은 이미 프로젝트 문서에 있다. 이 스킬은 코드로 옮길 때의 판단 규칙만 담는다.

- 표기 규칙·부호 모양: `docs/한국어_원고지_첨삭_지침.md`
- 게이트 실측: `docs/기획서_원고지첨삭앱.md` 5절, `examples/첨삭_실행결과.json`

## 부호 14종과 앵커

| kind | 한글 | 앵커 | 자동 첨삭 |
|------|------|------|-----------|
| space | 띄움표 | boundary (target 뒤) | 규칙 |
| join | 붙임표 | span | 규칙 약함 / LLM |
| insert | 넣음표 | boundary | LLM |
| punct | 부호 넣음표 | boundary | 규칙 |
| delete | 뺌표 | span | LLM |
| replace | 고침표 | span | LLM |
| swap | 자리 바꿈표 | span | LLM |
| newline | 줄 바꿈표 | boundary | LLM |
| joinline | 줄 이음표 | boundary | 교사만 |
| indent | 들여쓰기표 | span | 규칙 |
| outdent | 내어쓰기표 | span | 교사만 |
| up / down | 끌어 올림/내림 | span | 교사만 |
| stet | 되살림표 | span | 교사 기각 시만 |

boundary 계열은 `target` 바로 뒤 경계에 부호를 놓는다. span 계열은 `target` 범위 전체를 덮는다. `insert`·`punct`·`replace`는 `text`가 필수다.

교사 전용 부호를 LLM이 내면 게이트가 반려한다. 이유는 그 부호들이 **지면을 편집하는 도구**이지 학생 오류의 진단이 아니기 때문이다.

## 배치 규칙 (렌더러가 책임)

- 한 칸 한 자. 숫자와 로마자 소문자만 한 칸에 두 자
- 문단 첫 칸을 비운다. 들여쓰기표가 그 오류를 가리킬 때는 원문을 **들여 쓰지 않은 채** 그려야 오류가 보인다
- 마침표·쉼표·닫는 따옴표는 줄 첫 칸에 오지 않는다. 앞 줄에 매달거나 칸 밖에 둔다
- 첨삭 공간은 한 줄 띄기(`double_space`)가 만든다

## 첨삭 판단

표기 층은 맞고 틀림이 있다. 내용 층은 더 나은 선택을 권한다. 표기를 빨갛게 다 잡으면 내용 조언이 들어갈 자리가 없다. 그래서 초점 첨삭이 기본이고, 항목 수 상한이 있다.

- 문장 통째 교체는 고침표가 아니라 총평이다
- 간접 첨삭은 정답 글자를 □로 가린다. 자리와 종류만 남긴다
- 점수를 매기지 않는다
- 기각한 항목은 지면에 되살림표로 남긴다. 학생이 무엇이 되살아났는지 본다

## 게이트가 지키는 것

그릴 수 없는 항목을 버린다. 상세 한도는 `wongoji-engine` 스킬과 `chumsak_app.py`가 단일 출처다. 여기서는 이유만 고정한다.

- target이 본문에 없으면 자리가 없다
- span이 너무 길면 부호가 읽히지 않는다
- 같은 자리에 부호 둘을 그리지 않는다. 규칙 계층이 이긴다. 다만 **다른 종류의 이웃 오류**를 같은 구간이라고 한꺼번에 버리지 않는다
